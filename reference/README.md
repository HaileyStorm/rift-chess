# Executable reference — not the 3D game client

The runtime uses Python's standard library. Python 3.10+ syntax is required; the supplied execution receipt is from Python 3.13.5. `pytest` is a development dependency only. The eventual desktop player build must bundle its own application/runtime and must not require Python.

## Files and authority

| File | Role |
|---|---|
| `sliding_chess_sim.py` | Supplied generator, unchanged: ordinary moves, gaps, Shifts, reducers, old screening agents. |
| `rift_core.py` | **Final-rules interface:** validation, legal commits, canonical repetition, match control, replay and local bot. |
| `rift_cli.py` | Local NDJSON process adapter; no network, ports or model downloads. |
| `run_final_audit.py` | Reproducible 120-game audit with full action histories and explicit truncation. |
| `verify_package.py` | Replay saved experiments, rebuild fourteen parity fixtures, and verify orthodox perft depths 1–4. |
| `legacy/` | Original experimental runners, preserved for inspection rather than presented as final-policy tooling. |

The normative rulebook is `docs/01_RULES.md`. The inherited `terminal_status()` / `play_game()` use forced-100 adjudication and raw repetition keys; they are **not** the final match controller. `apply_action()` is an unchecked reducer for already-generated actions. Do not call it on unvalidated external intent.

## Reproduce the included evidence

From the package root:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
python reference/run_final_audit.py --workers 4
python reference/verify_package.py
```

The audit overwrites `research/fresh/` with newly generated records and metadata. Keep an original copy when comparing changes. Runtime seconds will vary; seeded action traces should reproduce under the same source/runtime. The fixtures are generated by this reference, so compare them with independent hand reasoning and additional tests rather than treating them as a proof that the reference is flawless.

Current included results: **67 tests passed; 120 histories replayed; 14,290 actions; 14 fixtures; 223 expected successors; orthodox opening perft 20 / 400 / 8,902 / 197,281.**

No legacy raw game histories were supplied. Legacy summary-only CSVs are retained under `research/legacy/`; their `draw_maxplies` outcomes must be treated as unfinished, not actual draws. The old runner scripts contain original `/mnt/data` defaults and module-path assumptions; do not present them as polished end-user commands. The final audit script resolves paths from its own package location.

## Use the Python API

When working from `reference/` or with that directory on your Python import path:

```python
from rift_core import Game, action_id, suggest

match = Game(layout="B", draw_policy="prompt")
legal = match.legal_actions()
match.step(action_id(legal[0]), expected_revision=match.revision)
proposal = suggest(match, depth=2, max_nodes=3000, seed=7)
match.step(proposal["action"]["id"], expected_revision=proposal["revision"])
record = match.export_record()
restored = Game.from_record(record)
assert restored.export_record() == record
```

`Game()` is deterministic and defaults to B-rift. The finished casual UI chooses B/C before constructing it; experiments choose explicitly. Search never mutates the match and returns the session/revision it searched. A production asynchronous caller must also match `game_id` before committing. A new/reset/imported game receives a new session ID.

The `suggest()` depth is a target, limited to 1–3 in this reference. Its node budget may stop an iteration; inspect `completed_depth` and `budget_exhausted`. It always returns a legal fallback when the match is ongoing. No strength rating is implied.

## Local NDJSON protocol

Run:

```bash
python reference/rift_cli.py
```

Send one complete JSON object per line. Responses are one line each, with the same string/integer/null `id`, an `ok` Boolean and either `result` or `error`. Non-finite JSON constants are rejected. The input limit is 1 MiB per line; replay action count is also bounded.

| Command | Relevant fields | Result |
|---|---|---|
| `new` | `layout`: B/C; `draw_policy`: prompt/auto100/off | New session observation |
| `observe` | Optional `game_id` | State, policy, result, rights, check and revision |
| `legal` | Optional `game_id` | Legal action metadata with stable IDs |
| `step` | `action_id`; optional `game_id`, `revision` | Committed state and last action |
| `suggest` | `depth`, `max_nodes`, `seed`; optional `game_id` | Version-bound local search proposal |
| `export` | Optional `game_id` | Full `rift-record/1` history |
| `load` | `record` | Validated, replayed record in a new session |
| `undo` | Optional `game_id`, `revision` | Practice rewind of one board action |
| `offer_draw` / `accept_draw` / `decline_draw` / `resign` | `actor`: +1/-1; optional `game_id`, `revision` | Match-control update |

The optional guards allow a minimal synchronous reference session. Production asynchronous clients should always send both guards for mutation. `undo` is an analysis tool here; a competitive UI must require consent or disable it. Actors are local logical sides, not authenticated remote identities.

A complete small synchronous exchange is:

```json
{"id":1,"command":"new","layout":"B","draw_policy":"prompt"}
{"id":2,"command":"legal"}
{"id":3,"command":"step","action_id":20825,"revision":0}
{"id":4,"command":"observe"}
{"id":5,"command":"suggest","depth":2,"max_nodes":3000,"seed":7}
{"id":6,"command":"export"}
```

Only `step` commits a suggested board move. Inspect the returned action rather than guessing its ID. The example's third command Shifts A2 → B2, so Black is then to act. `suggest` evaluates Black's response but does not play it.

## Formats and limits

Board shape **[64]**, signed piece codes with ±7 for a fresh pawn; hole mask is 16 bits with exactly two set bits. Stable action-mask shape **[21760]**; see the [engine design](../docs/04_ENGINE_AND_DELIVERY.md) for formulas.

`position_hash` identifies the canonical repetition position. It is not an authenticated file checksum or a full history-sensitive search key. The match's progress count, draw policy and repetition ledger remain separate. `Game.from_record` rebuilds that ledger from every action.

Arbitrary imported positions are structurally validated, not proved reachable from the opening. Record imports are checked by replay. Keep the reference local/trusted; a shipping exposed service requires additional resource, authentication and abuse controls and is outside the offline launch scope.

## Evidence limits

The test suite is focused rather than exhaustive. The bot is deliberately small. The experiments use weak policies and are not human playtests. The headless reference has no 3D rendering, asset pipeline, animation, accessibility layer, UI prompt-suppression state, installer or graphics performance measurements. Those are explicit requirements for the implementing agent, not silently completed features.
