# Rift Chess review and revised acceptance plan

Review date: 2026-10-05 UTC. Scope: analysis, plan update and supported task/Goal
rollover. No implementation campaign, compiler change, publication or purchase
occurred in the review. This document does not replace frozen Laws, normative
dependencies, proof authority or existing acceptance contracts.

## Diagnosis and activity versus delivery

Migration has stalled at integration, receipt and host-admission boundaries.
Many narrow compiler/lifecycle fixtures passed, but no accepted post-2.0.27 game
frame has followed. Visual updates then made migration caches/packages older than the
current visual source. Native proof/build gates rely on an unavailable executor.
Performance improvements have reduced particular costs without closing overall
responsiveness, and settled artwork quality does not carry through orbit motion.

Git records 94 commits in the explicit September 29 00:00Z through October 3 00:00Z
window. From `fc11252` to reviewed HEAD `4a0fd8c`, 209 files changed with 29,425
additions and 59 deletions, largely migration fixtures, adapters, supervisors and
evidence. The prior tracker was 2,193 lines/155,821 bytes. These are activity and
complexity measures, not hours of labor. Goal time/token counters were unavailable;
no estimate of actual labor is asserted. The direct 2.0.32 target was documented
September 29 and remained unadopted October 5; the user has now made 2.0.32 a
**minimum**, not a ceiling. The last three main commits concern
harness policy, rather than new game behavior.

## Release cutoff and migration candidate

The user corrected the version objective to **at least Bend 2.0.32**. At the
2026-10-05 06:22 UTC release cutoff, the [official latest stable release](https://github.com/bendlang/bend/releases/tag/v2.0.35)
is **2.0.35**, published October 3 at 11:32:50 UTC, target commit
`79df8d9c40722ee9507a1e253f283b51025f9d6c`. Choose it as the explicit
candidate for isolated evaluation, not as an adopted pin. The [2.0.33 release](https://github.com/bendlang/bend/releases/tag/v2.0.33)
reduces repeated conversion work and fixes several C/JS/checker cases; [2.0.34](https://github.com/bendlang/bend/releases/tag/v2.0.34)
shares equality comparisons but explicitly warns its `--verdict` kernel can
still exhaust fuel on such a proof. The 2.0.35 notes report library-name/CID
identity, CPU task and allocation reductions, list-cell lifetime, nested-sum
and template compilation, timer/deadline and several verdict fixes. These are
plausibly relevant to this sprint, not measured Rift wins or BendTT approval.

Review the exact upstream source/diffs and compatibility under the local guide
before a pin amendment. Newer releases after this cutoff change the target only
for a documented material safety/correctness fix or blocker removal; avoid a
rolling-latest chase. Existing 2.0.32 caches, tests, receipts and package are
historical/diagnostic inputs, not 2.0.35 validation. Keep accepted 2.0.27 and
all frozen laws and adoption gates until a separately reviewed amendment.

## Test and gate reduction

The repository inventory found roughly 80 `bend2/` paths with test-like names,
including fixtures and historical receipts, not 80 independent active gates.
The active 2.0.32 matrix itself says pre-phase-two selected-root, phase-four
coarse browser and individual proof shards are historical/diagnostic, while
the full 107-case Worker semantics and actual rendered browser behavior remain
unproved. The root TypeScript app separately runs `vitest run` and must remain
working. A long green test list is therefore a poor proxy for delivery.

Perform a bounded value audit before porting the matrix to 2.0.35: identify
each gate's real defect caught, overlap, cost, owner and whether it is frozen,
compatibility or historical provenance. Keep the cheapest independent witness
for each behavior and mandatory exact-byte/proof/security/native boundary.
Prefer an actual game frame and full interaction over chains of synthetic
unit-level compiler mirrors. Remove redundant active tests and their unused
helpers/fixtures together, including all unit tests that have no independent
value; do not set a deletion quota or remove a gate merely for being slow.
Schedule expensive proof/native/device runs at meaningful integration points,
with source hashes and retained failures, not after every small visual edit.
Document the reduced fast feedback set and the release/adoption set with
commands and wall-clock cost. Any change to a frozen gate follows its formal
policy; historical receipts remain readable but leave the active run list.
