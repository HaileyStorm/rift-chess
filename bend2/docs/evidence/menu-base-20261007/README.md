# Menu shell reuse in the isolated 2.0.35 preview

Opening a menu previously rebuilt the unchanged page shell. The browser now
retains the shell admitted by the existing `same_base` predicate and calls
`MenuAA.render_on_base`. Every call paints current text, board, panel/scrim and
controls in the original order. The six-argument `render` facade remains for
native callers and screenshots. A painted or dimmed menu is never the cached base.

The candidate menu binding adds one export independently of the shared selection
registry. The shared registry, all 315 prepared-proof inputs, its 62-module cone,
eight mutation controls and all 12 original `/2` consumer files remain exact.
The original combined proof execution remains creation evidence; this application
compatibility capture starts zero new proof Workers. Kernel and Linux runtime
approvals remain null. The original `/2` global revision gate deliberately does
not admit this application revision; the separate reviewed application manifest
authenticates every changed file and the original proof dependencies before
project imports. It grants no pin, Safe, kernel, native or device adoption authority.

First-playable median increased from 921.4 to 1082.7 ms and first-detail median

frame/memory budgets or constrained-device acceptance.

The measured boundaries are synchronous canvas writes and the next RAF
opportunity with passive observers in headless installed Chrome. Service workers
are blocked in fresh contexts. Physical display scanout, OS disk-cold startup,
owner graphics acceptance, native CPU/GUI/PCM/restart, unchanged original GPU
acceptance and compiler adoption remain separate requirements.
